# BEACON API Stability Policy

**Status**: Draft for Initiative H — 1.0 Stabilization (sign-off pending).
Effective from BEACON 1.0.0.

This document enumerates BEACON's committed public surface and the
backward-compatibility (BC) guarantee that applies to it. Anything not
listed as **Committed** is **Evolving** and may change in any minor
release without warning.

---

## 1. Versioning policy (SemVer 2.0.0 strict)

BEACON follows [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)
strictly from 1.0.0 onwards.

- **Major** (`X.0.0`) — breaking changes to any Committed surface item
  listed in §3.
- **Minor** (`1.X.0`) — additive changes (new optional fields, new
  endpoints, new CLI subcommands, new env vars). MUST NOT break any
  Committed surface item.
- **Patch** (`1.0.X`) — bug fixes only, no surface change.

### Deprecation path

To remove a Committed surface item:

1. **Announce in 1.X.Y CHANGELOG**: mark the item `### Deprecated`
   with the planned removal version.
2. **Emit `DeprecationWarning`** at runtime when the deprecated item
   is used.
3. **Remove in `2.0.0`** (or later major).

Additive replacements (new field/endpoint that supersedes the old
one) ship as minors in step 1.

## 3. Committed surface — detail

### 3.1 PIR output schema (`pir_output.json`)

The Pydantic model is `src/beacon/generator/pir_builder.PIROutputDocument`
and its dependencies. The JSON Schema is regenerated by
`cmd/generate_schemas.py` (now `beacon schema-regenerate` per §4) into
`schema/pir_output.schema.json`.

**Committed top-level**:
- `schema_version: "2.0.0"` — required string field; consumers gate on
  this. TRACE 2.0.0 accepts `{"2.0.0"}` only.
- `pirs: list[PIROutput]` — required, ordered.

**Committed `PIROutput` fields** (subset — see schema for full list):
- `pir_id`, `decision_point`, `priority`, `intelligence_level`,
  `collection_focus[]`, `valid_from`, `valid_until`
- `prioritized_actors[]` (from Initiative D + E)
- `mitre_attack_groups: list[str]` (Initiative F Phase 2)
- `score_breakdown: ScoreBreakdown` with:
  - `intent: IntentComponent` (score, motivation_alignment,
    industry_match, `ir_observed`)
  - `capability: CapabilityComponent` (score, sophistication_score,
    ttp_count_norm, recency_active_campaigns, tool_usage,
    targeting_persistence, evasion_capability, depth, breadth)
  - `opportunity: OpportunityComponent` (score, victimology_match,
    geographic_match, surface_ttp_coverage)
  - `data_quality: DataQualityComponent` (degraded, missing_sources,
    `ir_boost_skipped` — G Phase 6)
- `rationale: Rationale` (text, intent_factors, capability_factors,
  opportunity_factors)

**Additive (non-breaking)**:
- New optional fields on existing models.
- New `score_breakdown` sub-components (operator additions).

**Breaking (requires 2.0.0)**:
- Removing or renaming any required field.
- Changing `schema_version` to a non-`"2.X.Y"` value.

### 3.2 `sources_candidate.yaml`

Generated by `beacon pir-generate` (formerly `cmd/generate_pir.py
--sources-candidate`). Each entry follows the TRACE
`schema/sources.schema.json` shape (url, label, task, max_chars,
pir_ids, feed_type). URL field is the placeholder
`<TODO: fill from candidate>` for operator to fill.

**Committed**: top-of-file header structure (timestamp,
`schema_version: "1.0.0"`, Capability-window baseline note —
"BEACON 1.0.0 default-window (90-day) baseline"), per-entry header
comment shape (tier / region / industry / evidence_attack_groups),
the `pir_ids[]` association.

### 3.3 `collection_plan.md`

Markdown output covering P1-P4 entries: per-PIR section with priority
badge, intelligence level, collection_focus bullets, recommended
sources from `source_matcher`. Plus watch items (P3/P4) and
trigger-based collection actions.

**Committed**: section ordering (PIR section before watch items),
priority badge format (`[P1]` / `[P2]` / `[P3]` / `[P4]`),
"Recommended Sources" subsection presence.

### 3.4 `content_ja.json` + `content_ja.schema.json`

Multi-dimensional source/IR schema introduced in Initiative F Phase 1.7.

**Committed top-level sections** (cannot be renamed or removed):
- `intelligence_requirements: list` — CU-GIR Framework decimal IDs
  + 5W1H EEI + mitre_attack_groups
- `sources: list` — tier / region / industry_focus /
  evidence_attack_groups / tlp / requires_membership /
  evidence_derivation
- `trigger_actions: dict` — keyword → action descriptor
- `level_frequency: dict` — intelligence_level → frequency label
- `table: dict` — collection plan table labels (cti_team,
  ot_team, etc.)

**Additive (non-breaking)**:
- New entries in any list section (operator additions OK).
- New optional sub-fields on entries (e.g., `intelligence_requirements[]`
  gaining `valid_window_days`).

**Breaking (requires 2.0.0)**:
- Renaming any top-level section.
- Removing required sub-fields from entries.
- Removing the CU-GIR decimal ID convention from `gir_id`.

### 3.5 `source_aliases.json`

Hand-curated map of canonical publisher names to prefix patterns
matching ATT&CK `intrusion-set.external_references[].source_name`
variants. Operator can extend with additional publishers.

**Committed**: file format (dict[canonical_name, list[prefix_str]]),
location (`schema/source_aliases.json`).

### 3.6 `business_context.schema.json`

JSON Schema for the operator-supplied business context that drives
PIR generation. Used by `beacon assets-generate` and `beacon
pir-generate`.

**Committed**: top-level required fields (organization, industry,
geographies, business_critical_assets, ...) — see file for full list.

### 3.7 `beacon` CLI entry + subcommands (Phase 6 deliverable)

Initiative H Phase 6 introduces `beacon` as a click `Group` entry
point. Subcommands wrap the existing `cmd/*.py` logic. Operator-
visible surface from 1.0.0:

| Subcommand | Replaces | Purpose |
|---|---|---|
| `beacon pir-generate` | `cmd/generate_pir.py` | Generate PIR + collection plan + sources candidate |
| `beacon assets-generate` | `cmd/generate_assets.py` | Generate asset bundle |
| `beacon identity-generate` | `cmd/generate_identity_assets.py` | Generate identity (person/org) asset bundle |
| `beacon accounts-generate` | `cmd/generate_user_accounts.py` | Generate user account bundle |
| `beacon submit-review` | `cmd/submit_for_review.py` | Submit output to review system |
| `beacon taxonomy-refresh` | `cmd/update_taxonomy.py` | Sync threat taxonomy from MITRE ATT&CK + MISP Galaxy |
| `beacon misp-cache-refresh` | `cmd/refresh_misp_cache.py` | Refresh MISP taxonomy cache |
| `beacon web` | `cmd/web_app.py` | Launch review UI without triggering PIR generation |

**Committed**: subcommand names + each subcommand's main flags (e.g.,
`pir-generate --output`, `pir-generate --no-sage`,
`pir-generate --sources-candidate`).

**Evolving**: optional flag defaults (e.g., `--taxonomy` default), help
text wording, output formatting.

**Removed in 2.1.0**: `python -m cmd.<name>` invocation syntax.
Standalone `__main__` blocks and `DeprecationWarning` machinery were
removed. Use `beacon <subcommand>` exclusively.

### 3.8 BEACON web UI (`beacon web`)

Launch the web UI separately with `beacon web` after `beacon pir-generate` completes.

**Committed route paths** (HTML/CSS internals remain Evolving):
- `/` — landing page listing all generated artifacts in the most
  recent output directory: `pir_output.json`, `assets.json`,
  `identity_assets.json`, `user_accounts.json`,
  `collection_plan.md`, `sources_candidate.yaml`.
- `/review/pir/{pir_id}` — `prioritized_actors[]` view + edit
  (exclude / manual_likelihood_override / rationale_append). Edits
  persist in session only (no SAGE write-back); export to JSON
  for downstream operator workflow.
- `/review/artifacts/{filename}` — read-only viewer for the other
  artifact files.

**Evolving**: HTML structure, CSS, JavaScript, internal API routes
serving the UI.

### 3.9 Environment variables (Committed)

| Env | Default | Purpose |
|---|---|---|
| `ACTIVITY_WINDOW_DAYS` | `90` | Capability `recency_active_campaigns` window. Operator sets `180` for 6-month trend mode |
| `BEACON_IR_LOOKBACK_DAYS` | `365` | SAGE `GET /api/incidents` query window for IR-boost computation |
| `SAGE_API_URL` | `""` | SAGE REST API URL. Empty = no SAGE call (same as `--no-sage`) |
| `SAGE_API_AUTH_TOKEN` | `""` | Bearer token for SAGE API. Send when set; absent header otherwise |

**Other env vars** (deployment-specific, NOT committed):
- LLM model selection: `BEACON_LLM_SIMPLE`, `BEACON_LLM_MEDIUM`,
  `BEACON_LLM_COMPLEX`, `BEACON_LLM_MAX_OUTPUT_*`
- GCP: `GCP_PROJECT_ID`, `VERTEX_LOCATION`
- GitHub Enterprise: `GHE_TOKEN`, `GHE_REPO`, `GHE_API_BASE`

These may change name or default in minor releases — operators set
them explicitly per deployment.

## 4. Evolving (NOT BC-protected)

The following are documented for operator awareness but are NOT
under the BC guarantee. They may change in any minor release.

- **Internal Python modules** under `src/beacon/` not exported via
  the documented API surface. Underscore-prefixed and undocumented
  helpers may change without notice.
- **`generate_schemas.py`** (or its `beacon schema-regenerate` form)
  — dev tool for regenerating JSON Schemas from Pydantic models.
  Operators do not invoke this directly.
- **HTML/CSS/JavaScript** in `src/beacon/web/templates/` and
  `src/beacon/web/static/`. The route paths (§3.8) are committed
  but the rendered HTML structure may change to add features.
- **`schema/asset_tags.json`** — operator-curated tag taxonomy.
  BEACON may add default tags in minors.
- **`schema/surface_ttp_map.json`** — surface→TTP mapping data,
  refreshed from external sources.
- **`schema/threat_taxonomy.json`** — auto-generated from MITRE
  ATT&CK + MISP Galaxy via `beacon taxonomy-refresh`.
- **`schema/trigger_keywords.json`** — trigger keyword data,
  evolving with annual threat-report ingestion.

## 5. Cross-repo dependencies

BEACON's Committed surface depends on:

- **TRACE `schema/sources.schema.json`** (TRACE 1.12.0+) for
  `sources_candidate.yaml` validation.
- **SAGE `GET /api/incidents`** (SAGE 1.0.0+) for IR-boost in
  `beacon pir-generate`.
- **MITRE ATT&CK Enterprise STIX bundle** (read at derivation time,
  not committed into BEACON repo) for `source_attack_groups.derived.json`
  regeneration.
- **Intel 471 CU-GIR Framework** (GitHub STIX JSON) for IR `gir_id`
  taxonomy keys.

Full citation inventory: `docs/citations.md`.

## 6. 2.0.0 trigger examples

Documenting what kinds of changes would force a 2.0.0 release helps
operators reason about the BC guarantee:

- Removing `schema_version` field from `pir_output.json`.
- Renaming `intelligence_requirements` → `requirements` in
  `content_ja.json`.
- Changing the Likelihood formula from `Intent × Capability ×
  Opportunity` to a non-multiplicative form (changes numerics).
- Removing `beacon pir-generate` subcommand or its `--output`
  flag.
- Removing `BEACON_IR_LOOKBACK_DAYS` env var.
- Removing the `/review/pir/{pir_id}` web UI route.

Adding new fields, new endpoints, new subcommands, new env vars is
always allowed in minor releases as long as defaults make existing
deployments behave unchanged.
